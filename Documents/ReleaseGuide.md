# 世界拡張版の更新・保存復旧

対象：2.3.0 / 保存v14。2026-10-03。

2.3.0はスキーマ変更がなく、2.2.0と同じv14保存を使用します。読込時に既存の在庫・資金・貨物・運行・投資設定は変更しません。次の月次判断から競合の自主投資が始まり、将来の市場や競争は変化します。2.2.0へ戻す場合は保存用2.2.0ブランチと更新前のJSONを組み合わせてください。保存が互換でも、新旧版でその後のシミュレーションは一致しません。

1. 現在の画面で保存・JSON書き出しを行い、同じURLを再読み込みします。「再開」から既存の保存を選択してください。ブラウザのホスト・ポートが異なると保存領域も異なります。
2. v1～v13を凍結した旧検証器で確認してからv14へ移行します。v13からは保存バージョンだけを更新します。以前の版からの移行では、旧市場・現金・研究・船名・貨物・航海残日数・航路・許可品目・外交状態・乱数を維持し、追加市場・品目・国家間関係を投入します。
3. v12の既存66港間の距離は不変。旧航路で茶・絹等を運ぶには積載条件で許可してください。新設ルートは全品目が初期許可です。
4. 保存先はv14へ分離。旧スロットと地峡交易追加前等の保全保存を残し、「キャラバン追加前の保全保存」に正常な元JSONを一度だけ保持します。ブラウザ容量不足時はJSON書き出しを使ってください。ファイル読込の上限は50 MBです。
5. 旧版へ戻す場合は更新前のアプリ・JSONを組み合わせます。2.0.0ブランチと更新前のv13保存を使用できます。v14から旧形式への逆変換はありません。読込失敗時に現在の会社は変更しません。
6. v12からSuez・Panama Cityの2港と2道路を追加します。既存市場・道路権・道路投資・運行中の馬車も維持します。地図の地域選択と「陸上交易と道路」のエジプト・パナマ設定ボタンを使ってください。
7. 全景はラベルを絞っています。地図の＋／−・ホイール・背景ドラッグ、地域選択、「都市へ移動」を使用してください。拡大後も港間ドラッグや巡回のクリック選択が使えます。

8. 陸上交易の開設画面で馬車・ラクダ・ラバを選べます。所要日数比較・必要資金を確認してください。旧馬車の所要日数・積み荷・運行中の残日数を維持します。

## 再現できる検証

```powershell
npm test
npm run test:campaign
npm run benchmark:scale
npm start
```

- `npm test`は従来機能・旧版移行に加え、翻訳の欠落とプレースホルダー、6言語の描画と状態不変、保全保存、3シード×18,250日の統合検証を含みます。
- 長期試験は通常の初期資金から交易し、技術投資、設備取得、設計・建造、都市投資、予算付き増減船・補充、見えている友好度を基準にした外交投資を行います。毎年、復元した世界と次の1日の完全一致を検証します。
- `benchmark:scale`は人工的な資金を与えた200隻・200航路で1年を実行します。これは負荷試験であり、その航路構成の経営効率を示すものではありません。
- 起動後の `/scripts/browser-benchmark.html` で「Run benchmark」を押すと、同規模の地図・選択中航路のDOM更新を16倍速・10秒計測します。ページを表示したまま測ります。利用者の保存領域は読み書きしません。**完全なゲーム画面全体のFPS測定ではありません。**

## 更新前後

1. 旧版で一時停止し、手動保存する。「書き出し」からJSONを別ファイルに保管する。ダウンロードできなければ同画面のテキストを`.json`ファイルに保存する。
2. 同じホスト名・ポートで新版を起動する。別ポートやブラウザでは保存領域が別になるため、JSONを移す。
3. 新版の初期画面は新会社。「再開」から元の保存を選び、日付・現金・船・航路を照合してから進める。
4. P6で最初に保存を更新するとき、既存の有効スロットのうち経過日数が最大のものを、元のJSONのまま「保全保存（P6）」へ一度だけ残す。同日ならスロット定義順（手動が自動より先）を優先する。過去の別会社の方が長期間なら、そちらが選ばれる場合があるため、手順1の手動書き出しも行う。
5. 保全スロットは以後の自動・手動保存で更新しない。通常の「前回の保存」は引き続き世代交代する。最初から既存保存がない新規利用では、次に既存の正常保存が見つかった保存時点で保全する。

旧v1～v5は既存の移行処理でv6へ読み込めます。v6の設計・名前・航行状態も維持します。元の旧スロットには書き込みません。保存形式が同じでも旧アプリが新しい項目に対応する保証はないため、旧アプリへ戻す際は更新前に書き出したJSONを使います。

## 復旧

- 破損データは「再開」で無効表示になります。他の手動・自動・前回・保全・旧版の有効スロットを選びます。読込失敗時は現在の会社を差し替えません。
- 「保全保存（P6）」は破損していても勝手に上書きしません。正常な別スロットや書き出しファイルから復旧します。
- 保存容量不足や利用禁止では、更新処理を中止して警告します。保全コピーに失敗した場合も既存本体を上書きしません。進行を止め、JSONを書き出してください。
- ブラウザデータ削除は全スロットに及びます。保全保存は別媒体へのバックアップではありません。
