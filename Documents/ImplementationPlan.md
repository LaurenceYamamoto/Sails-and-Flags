# Sails and Flags: 実装・リリース計画

作成日：2026-09-29  
状態：ドラフト  
設計の基準：[ゲームコンセプト](Concepts.md)

実装状況（2026-10-03）：現行2.1.0 / 保存v14。P8の世界地図・68港＋46内陸・23国家・20品目、ライバル各50航路、地図の拡大縮小・移動を実装。旧セーブ移行と世界航路・負荷を検証。西欧以外を含む69道路と地域別道路一覧を実装。エジプト・パナマの海域間陸上連絡と設定プリセットを追加。ラクダ・ラバと地形適性・比較表示を実装。季節風・文化嗜好の詳細、競合の自主的な技術・都市・道路投資は未実装。外部ブラウザ・実機タッチ・人による翻訳確認も引き続き課題。[結果報告](../ImplementationNote.md)を参照。

## 1. 計画の目的と前提

全世界・全機能を一度に実装するのではなく、交易の基本サイクルを小規模に成立させ、プレイ検証を重ねながら経営判断の幅を広げる。最初に検証する体験は「価格差を発見し、交易路を設定し、自動運航による利益を船と交易網に再投資すること」とする。

- 初期の交易都市は、カリブ地域と西ヨーロッパのイギリス、フランス、オランダ、ポルトガル、スペインに限定する。
- 初回の外部公開版と地域限定正式版 v1.0 は、この地理的範囲を維持する。
- 初期は海上交易を優先し、陸上交易は v1.0 後に同じ地域内で導入してから、世界の他地域へ拡張する。
- ブラウザ向け2D・シングルプレイとし、1日単位のリアルタイム進行、一時停止、速度変更、セーブを早期に実装する。
- コンセプトの仕様は最終的な到達目標とする。後段へ送る機能は未実装として明示し、簡略化した仕様を完成形として固定しない。
- 開発人数・予算・既存技術基盤が未確定のため、日付による納期は置かない。各段階の完了条件を満たしてから次へ進み、最初の試作後に実績から工数を見積もる。

この文書で用いる都市数、品目数、検証期間は、開発規模を制御するための仮置きであり、プレイ検証で調整する。

## 2. 初期地域とコンテンツの範囲

### 2.1 地域の扱い

初期マップは、カリブ海・北大西洋・指定5か国の港を結ぶ海上交易に必要な範囲とする。大西洋は輸送距離・所要時間・費用を持つ海域として扱う。対象外地域には交易可能な都市を置かず、マップ外との取引機能も設けない。

都市の所属国家は固定する。カリブ地域の都市にも所属国家を設定し、ヨーロッパ側と同じ国家別の交易免許を適用する。国名の表記、1700年ごろの港の位置・所属・交易品は、コンテンツ確定時に確認する。

### 2.2 都市の段階的な追加

| 段階 | 都市数の目安 | 選定方針 |
| --- | --- | --- |
| 内部試作 | 4都市 | カリブ側2都市、ヨーロッパ側2都市。近距離交易と大西洋横断交易を比較できる組み合わせ |
| 初回外部公開 | 12都市程度 | 指定5か国に各1港以上、カリブ側に複数の生産・消費特性を持つ港を配置 |
| 地域限定 v1.0 | 12～16都市 | 必要な場合のみ追加。都市数の増加より、航路・市場・外交の選択肢の違いを優先 |

候補都市は以下とする。これは採用確定リストではなく、史実確認とゲーム上の役割の検証を経て絞り込む。

- イギリス：ロンドン。追加候補はブリストル。
- フランス：ナント。追加候補はボルドー。
- オランダ：アムステルダム。
- ポルトガル：リスボン。追加候補はポルト。
- スペイン：カディス。
- カリブ地域：ハバナ、サンティアゴ・デ・クーバ、サントドミンゴ、サンフアン、キングストン、ブリッジタウン、ウィレムスタット。

試作では短距離航路を持つ地域から開始できるようにし、最初から大西洋横断に必要な資金を要求しない。横断航路は、運営資金と輸送能力を増やした後の成長目標にする。

### 2.3 交易品・船の規模

- 試作は4～6品目、初回外部公開は8～12品目を目安とする。砂糖、タバコ、ラム酒、織物、工具、木材、食料などを候補とし、各都市の生産・消費設定で交易の方向性を作る。
- 武器は、戦争による需要・価格変化を導入する段階で追加する。
- 都市ごとの生産と需要はゲーム用に集約する。対象外地域からの輸入を暗黙の前提にせず、初期地域だけで市場が持続する設定を検証する。
- 試作の購入船は2種類、外部公開では3～4種類を目安とする。速度、積載量、運用費、航続距離の違いによって、近距離と長距離で選択が変わるようにする。
- 技術力はゼロから開始し、造船の導入までは船を購入で取得する。

## 3. 実装順序の原則

1. **市場と会計を先に固める。** 売買・在庫・価格・現金の整合性は、競合、自動化、投資の共通基盤になる。
2. **基本の自動化を試作に含める。** 自動運航と自動積載は中核機能であり、手動の品目・数量指定を前提とした別の遊びで代用しない。
3. **固定条件から動的な条件へ進める。** まず固定の税・免許条件で採算を検証し、その後に競合の判断、襲撃、外交変動を追加する。
4. **危険を追加するときは、対策と説明も実装する。** 襲撃には護衛と被害履歴、免許取消には友好度表示と事前通知を同時に用意する。
5. **長期投資は短期収益が成立した後に追加する。** 技術・造船・都市開発の費用対効果を、既存の交易収益と比較できる状態にする。
6. **地域拡張はデータ追加を基本にする。** 都市、国家、品目、船種、航路を識別子で管理し、特定の港や国家をコードに直接埋め込まない。

主な依存関係は、`市場・会計 → 自動交易 → 複数航路・競合 → 高度な自動化 → 危険・外交 → 長期投資 → 品質検証` とする。陸上交易は輸送の共通基盤を利用し、世界拡張は海陸両方の検証後に進める。

## 4. 段階別の実装と公開範囲

### P0：仕様の確定とシミュレーション基盤

**目的：** 後続機能が共通して使用するルールとデータ形式を固める。外部公開はしない。

実装・設計内容：

- ゲーム内の日付、日次更新順序、一時停止、速度変更の基盤。
- 都市・国家・交易品・輸送手段・交易路・会社のデータモデル。輸送手段には将来の陸上交易に必要な拡張点を置くが、陸上の挙動は実装しない。
- 在庫、生産、価格に応じた需要変動、価格計算、売買処理。
- 数量に応じて変動する価格を区間全体で計算し、同一条件の分割売買と一括売買が丸め誤差の範囲で一致する仕組み。
- 現金・積み荷・船の記録、仕入・売上・運営費・一時投資を追える会計記録。保有資金がマイナスになった時点でゲームオーバーにする。
- セーブ形式のバージョン管理、乱数シードを固定できる検証用実行環境、画面文言の翻訳キー。
- 日次処理と売買処理の順序、丸め、税計算、資産評価、各種利益率を仕様化する。船の取得費と運営費を区別し、二重計上を防ぐ。

完了条件：

- 売買による現金と在庫の移動、在庫不足時の約定、分割売買の同等性を自動検証できる。
- 同じ初期状態・操作・乱数シードから同じシミュレーション結果を再現できる。
- セーブとロードで日付、現金、在庫が維持される。

### P1：交易サイクルの内部試作

**目的：** 4都市程度で「発見・設定・輸送・販売・再投資」を一巡させ、面白さを確認する。

実装内容：

- 2D地図、都市の価格・在庫・生産・需要表示、購入船2種類。
- 海上の航路と距離、航続距離制約、日次の移動・到着・売買・運営費処理。
- 2都市間の往復交易路の設定、複数船の割当、停止・再開、自動反復運航。同一の港の組は往復の向きによらず1ルートとし、隻数に応じて等間隔に出港するよう自動調整する。
- 船の購入場所・未使用船の所在地は設定しない。保有枠からルートに直接配置し、航行中の解除は到着・売却後に行う。
- 許可品目と最低価格差（％）を設定し、出発時点の予想利益を最大化する自動積載。積載量、所持金、市場在庫、数量による価格変動を考慮する。
- 利益条件を満たす積み荷がない場合や片道だけ積載する場合の運航規則。出発時の予測と到着時の実績を区別する。
- 固定条件の交易免許取得・維持費と取引税。外交変動はまだ発生させない。
- 航路の実績収支、往復所要時間、期間あたり利益、現金残高の表示。
- 手動セーブ・ロード、一時停止・速度変更、現金不足によるゲームオーバーと結果表示。

完了条件：

- 通常の画面操作だけで、船の購入から交易利益による2隻目の購入まで到達できる。
- 同じ航路の反復による在庫・価格変化が採算に反映され、航路を見直す意味がある。
- 短距離と横断航路について、航海中の資金繰りを含めた採算を説明できる。
- 航行中に保存・再開しても、積み荷や売買が消失・重複しない。

この段階で面白さが確認できなければ、都市数や機能を増やさず、市場・距離・費用・情報表示を調整する。

### P2：地域限定MVP／初回外部公開アルファ

**目的：** 指定地域内で複数航路を経営できる最小構成を公開し、基本体験への反応を得る。

実装内容：

- 約12都市、指定5か国の免許、8～12品目、購入船3～4種類へ拡張。
- 複数の交易路・複数隻の管理、未使用船のインベントリ、収益順の航路一覧。
- 複数港を巡る航路と中継交易。中継港では積み荷を市場価格で売却し、次区間向けに再購入する。無償の積み替えとして扱わない。
- 固定航路で売買する少数の競合。競合にも市場在庫と価格変動を適用し、プレイヤーと同じ売買計算を使う。
- 都市詳細、航路別収支、会社全体の収支・資産推移、原因を追える取引履歴と赤字通知。
- 開始ガイド、自動セーブ、破産前の資金不足警告、セーブの書き出し・読み込み。
- 日本語・英語の画面文言と翻訳切替。残りの対応言語は v1.0 までに追加する。

公開条件：

- 初見のテスターが、ガイドを使って初回の黒字交易と航路追加を行える。
- ゲーム内10年相当の自動運転で、負在庫、無効な価格、船の重複、進行停止が発生しない。
- 売買の分割や中継によって無限に利益を作れる不具合がない。
- セーブ復元と主要画面を対象ブラウザで検証し、進行不能・保存不能の既知の不具合を解消している。

公開時には、海賊、動的外交、造船、都市開発、陸上交易が今後の実装であることを明示する。アルファ版でセーブ互換性を維持できない更新は、公開前にリセット対象と理由を知らせる。

### P3：競合と交易網の自動管理

**目的：** 市場を巡る競争と、複数航路を育てる経営判断を成立させる。アルファ版を更新する。

実装内容：

- 小規模商人と大規模交易会社の判断・資金・資産管理。競合による航路の選択と拡張、地図上の競合航路表示。
- 資産ランキングと、初めて資産総額1位になった際の経過期間記録・通知。達成後もサンドボックスを継続する。
- 競合の買収。保有現金、船、積み荷、航路の引継ぎと二重計上防止。以降に追加する権利・投資も引継ぎ対象として拡張する。
- ユーザー設定の利益率閾値に基づく航路容量の自動拡大・縮小。拡大は利益率の高い航路から優先する。
- 自動化の月間予算と最低保有資金、実行理由・見送り理由の履歴。
- 拡大・縮小後はその航路の1往復分の期間、自動調整を停止する。縮小で航路を廃止せず、余った船はインベントリへ戻す。

完了条件：

- 自動調整の利益率は、コンセプトどおり輸送手段自体の利益÷経費とし、護衛費など航路全体の固定費を含めない。経費ゼロ時の扱いを定義する。
- 航路全体の採算も別に表示し、自動調整用の利益率との違いを説明できる。
- 拡大閾値が縮小閾値を下回る設定を拒否し、月次境界や複数航路の同時処理でも予算・最低保有資金を守る。
- 競合の活動によって収益機会が変化し、買収前後の資産・市場状態が整合する。

### P4：海賊・護衛と動的外交

**目的：** 収益性に加えて危険と国家関係を管理する。機能追加版として順次公開する。

実装内容：

- 海賊の襲撃、積み荷損失、まれな船の喪失、護衛船、商船の砲門数・速度による被害軽減。戦闘は自動処理する。
- 船喪失時の自動再購入。P3の共通予算管理を利用し、拡大との優先順位や月間枠の消費を明示する。
- 国家ごとの友好度、交易・敵国との交易・資金投入による変化、免許費・税への影響。
- 国家間の開戦・終戦、通知、武器価格への影響。史実上の関係と距離を踏まえた発生条件と数年～10年程度の継続期間。
- 友好度に基づく免許取得制限・取消、入港禁止、残存船の未使用インベントリへの返却、著しい敵対時の海上妨害。
- 危険度、護衛費、被害、外交の変化理由、取消閾値までの余裕を表示する。

完了条件：

- 開戦だけで免許を即時取消にしない。友好度に十分な余裕を持ち、投資を続ければ戦時でも取消を回避できる。
- 護衛なし・護衛ありの費用と損失を比較し、安全対策の効果を確認できる。
- 航行中・寄港中・積載中の取消や船喪失でも状態が破綻しない。取消時の積み荷処理は実装前に仕様を確定する。
- 自動再購入と自動拡大が同時に発生しても、共通の予算・最低保有資金制約を守る。

### P5：技術・造船・都市開発／機能完成ベータ

**目的：** 交易利益を長期的な優位に変える成長要素を導入し、地域限定版の機能を揃える。

実装内容：

- 継続投資による造船技術・海上交易技術の向上。投資額に上限を置かず、効率を逓減させる。
- 技術と設備条件を満たした後の造船、新船種の解放、建造前の設計研究。
- 積載量・速度・武装の連続的な変更、ソフトキャップ、運用費を含むトレードオフ。建造後の改良は行わない。
- 都市開発権の取得、都市規模・生産力への投資、税収の一部受取。国家からの購入と既存所有者からの購入を扱う。
- 免許取消時の開発権・投資の無補償没収、競合買収時の権利・投資の引継ぎ。
- 継続投資の一覧・変更・停止と、一時投資、日常の運営収支を区別した表示。

完了条件：

- 交易、技術投資、造船、都市投資の効果を収支と市場変化で確認できる。
- 都市成長を物資充足の条件にせず、投資で増えた需要・生産を交易に活用できる。
- 都市投資と税収だけで稼ぐ戦略が、交易を行う戦略より有利にならないことを比較検証する。
- 万能船が支配的にならず、距離・危険・貨物量に応じて船の設計に選択の余地がある。
- 技術・都市開発への投資は資産ランキングに計上しない。開発権など評価ルールが必要な資産は、P0で定めた方式で統一する。

### P6：地域限定正式版 v1.0

**目的：** P2～P5を統合した海上交易ゲームとして、初期地域内で安定して遊べる状態にする。

実施内容：

- 日本語、英語、中国語、韓国語、フランス語、スペイン語の6言語対応。中国語の字形・ロケール範囲は翻訳着手前に決める。
- 文字数差、フォント、数値・日付表記、通知、ガイドの表示確認。
- 市場、競合、外交、襲撃、投資、自動化を組み合わせた長時間検証とバランス調整。
- 初回起動から資産1位達成、達成後の継続、破産、セーブ復旧までの通し確認。
- 対象ブラウザ・基準端末を明記し、地図操作、最大速度、想定最大規模の航路・船数で性能を測定する。
- セーブ移行処理、更新前のバックアップ、読み込み失敗時に既存データを上書きしない復旧手順、リリース手順の整備。

公開条件：

- 進行不能、データ破損、会計不整合に該当する既知の不具合がない。
- 複数の乱数シードでゲーム内50年相当を実行し、経済・競合・外交が継続して動作する。
- テスターが利益・赤字・襲撃損失・免許取消の原因を画面から追える。
- P0で定義する性能基準と、6言語での主要操作・保存・復元の確認を満たす。

v1.0 は「地域限定・海上交易版」として公開する。全世界・陸上交易を含むコンセプト全体の完成とは区別する。

### P7：陸上交易の追加／v1.x

実装済み（2026-10-02、1.1.0-alpha.2）。自動テスト・実ブラウザ検証と仕様上の制限は[初期P7の作業記録](../AgentNote/2026-10-02-p7-land-trade.md)と[都市再選定の記録](../AgentNote/2026-10-02-p7-city-selection.md)を参照。

**目的：** 地理的範囲を大きく広げず、海陸の輸送網を接続する。

- 交易上の役割と地理的な接続を重視して選定する内陸拠点・主要港と接続路（各国一律の配置は行わない）を追加し、まず馬車を導入する。
- 地形、道路、陸上の通行免許、通行料、地域ごとの治安基準値と投資効果、襲撃者、護衛者を実装する。
- 陸上交易路の開発権、道路改善、通行料収入、陸上交易技術への継続投資を追加する。
- 自動積載、自動拡大・縮小、自動再購入、会計、資産比較を陸上輸送へ適用する。
- 免許取消時の通過禁止、輸送手段の返却、都市・交易路の権利と投資の没収を検証する。
- 海陸接続でも中継都市の市場で売買するルールを維持し、接続した交易網の採算を確認する。

完了条件は、海上のみ・陸上のみ・海陸接続の交易を比較でき、地形と道路への投資に経営上の意味があり、既存の海上プレイとセーブが正常に動作することとする。

### P8：世界の段階的拡張／v2.0以降

第1地域を実装（2026-10-02、2.0.0-alpha.1）：西地中海のGenoa・Livorno、2国家、オリーブ油、競合1社。既存のBarcelona・Marseilleから接続でき、既存港間距離を維持する。都市数の国別均等化は行わず、海上交易の役割と既存経済との接続を優先。世界地図・主要港は次項の世界拡張で対応。この時点でキャラバンは未着手（2.1.0で後続実装）。[選定・検証記録](../AgentNote/2026-10-02-p8-mediterranean.md)。

**目的：** 検証済みの輸送・市場・国家モデルを利用し、全世界の構想へ広げる。

- 隣接海域と接続しやすい地域から候補を比較し、地域ごとに都市・国家・品目・航路をまとめて追加する。順序は v1.x の結果を踏まえて別途確定する。
- 砂漠地域の追加に合わせてラクダ、山岳・悪路の交易需要に合わせてラバのキャラバンを導入する。
- 地域ごとの治安・気候・嗜好・政治勢力の集約と、競合会社を追加する。
- 拡張ごとに免許・外交・供給と需要・長距離輸送の資金繰りを再検証する。遠距離国家間の不自然な戦争も防ぐ。
- 全世界規模の都市・航路・競合数に応じて、シミュレーションと表示を最適化する。

各地域の公開条件は、追加地域内と既存地域への接続航路が成立し、既存経済への影響、性能、翻訳、セーブ移行を確認できることとする。都市数だけを増やす一括拡張は行わない。

## 6. リリース運用と検証方針

- 各段階の終わりに、動作するブラウザ版、実装範囲、既知の問題、検証結果、セーブ互換性をまとめる。
- 初回外部公開はP2とし、P0・P1は内部検証に使う。以降はP3・P4でアルファ更新、P5でベータ、P6でv1.0とする。
- 公開後は、保存・進行・会計の不具合を新機能より優先する。公開版を再配布できる状態で保持し、不具合時の復旧とセーブ保護を確認する。
- v1.0以降は公開版セーブの移行をリリース条件とする。不可避の非互換変更は通常更新から分け、事前告知と旧セーブの保全手段を用意する。
- 経済計算は自動テスト、経営全体は固定シナリオ・複数シードの長時間実行、理解しやすさは人によるプレイで検証する。
- 自動化、買収、襲撃、取消、セーブが重なる場面は、機能を個別に検証した後に組み合わせて確認する。
- 初回黒字までの経過、2隻目の取得までの経過、破産原因、航路の偏り、赤字理由の理解度をプレイテストで記録し、次段階の調整に使う。

## 7. 主なリスクと調整方針

| リスク | 対応する段階と方針 |
| --- | --- |
| 大西洋横断の時間・費用が序盤を停滞させる | P1で短距離航路から成長する流れを検証し、横断中の運営資金を見積もれるようにする |
| 自動積載が利益を取り逃がす、または計算負荷が高い | P1で小規模な総当たり結果と比較し、P2以降の品目・船数増加時に精度と速度を測る |
| 市場が極端な価格に張り付く、同じ航路だけが有利になる | P0～P2で需要反応と在庫変化を検証し、P3以降で競合を含めて再調整する |
| 外交と襲撃による損失が予測・対策不能になる | P4で情報表示と対策を同時に導入し、管理可能性をプレイテストする |
| 投資や税収が交易より有利になり、主題が薄れる | P5で交易を伴う戦略と投資だけの戦略を比較する |
| 初期地域を超えた仕様を作り込み、公開が遅れる | P2の範囲を固定し、新しい地域・陸上輸送はP7以降へ置く |
| 更新で既存の進行状況が失われる | P0から保存形式を版管理し、P6までに移行と復旧を公開工程に組み込む |
